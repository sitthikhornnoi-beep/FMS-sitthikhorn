# Product Requirements Document (PRD)
## Feature 4: ระบบบริหารจัดการและอนุมัติเอกสาร (E-Document & Approval Workflow)

---

## 1. บทสรุปและวัตถุประสงค์ (Executive Summary & Objective)

ระบบบริหารจัดการและอนุมัติเอกสาร (E-Document & Approval Workflow) เป็นระบบสารบรรณและหนังสือราชการอิเล็กทรอนิกส์สำหรับคณะวิทยาการจัดการ ออกแบบมาเพื่อยกระดับการทำงานสู่ **Paperless Organization** ลดขั้นตอนการเดินส่งเล่มเอกสาร ป้องกันการสูญหาย และเพิ่มความโปร่งใสตรวจสอบได้ของเส้นทางเอกสาร (Audit Trail)

### วัตถุประสงค์หลัก:
1. **ลดระยะเวลาการเดินเรื่องและเกษียนหนังสือ**: เปลี่ยนจากการเสนอแฟ้มกระดาษเป็นการส่งต่อและลงนามดิจิทัลผ่านระบบเว็บ
2. **ออกเลขทะเบียนหนังสืออัตโนมัติ**: ควบคุมการรันเลขสารบรรณตามระเบียบงานสารบรรณ แยกตามประเภทหนังสือและปี พ.ศ. ป้องกันการข้ามเลขหรือเลขซ้ำ
3. **ติดตามสถานะแบบ Real-time (Tracking Timeline)**: ผู้ยื่นเรื่องและผู้เกี่ยวข้องสามารถตรวจสอบได้ทันทีว่าเรื่องอยู่ที่ใคร อยู่ในขั้นตอนใด
4. **ความปลอดภัยและการกำหนดสิทธิ์ตามชั้นความลับ**: ปกป้องเอกสารลับเฉพาะบุคคล และรองรับการทำงานตามบทบาท (RBAC)

## 2. กลุ่มผู้ใช้งานและบทบาท (User Personas & Roles)

| กลุ่มผู้ใช้งาน (Persona) | บทบาทในระบบ (Role) | สิทธิ์และความรับผิดชอบหลัก |
| :--- | :--- | :--- |
| **อาจารย์ / เจ้าหน้าที่ทั่วไป**<br>(Faculty & Staff) | `document:create`<br>`document:read` | • สร้างบันทึกข้อความ (Internal Memo) และคำขอโครงการ<br>• ติดตามสถานะเอกสารของตนเอง<br>• อ่านเอกสารที่ตนเป็นผู้รับเรื่อง |
| **เจ้าหน้าที่งานสารบรรณคณะ**<br>(Central Registrar / Clerk) | `document:manage`<br>`document:register` | • ลงรับหนังสือภายนอก (Incoming)<br>• ออกเลขหนังสือส่งภายนอก (Outgoing), ประกาศ, คำสั่งคณะ<br>• ตรวจสอบความถูกต้องของแบบฟอร์มก่อนเสนอผู้บริหาร |

## 3. ขอบเขตและฟังก์ชันการทำงาน (Functional Requirements)

### FR1: การสร้างและยื่นเสนอเอกสาร (Document Creation & Submission)
- รองรับประเภทเอกสารราชการ:
  1. `MEMO` - บันทึกข้อความภายใน
  2. `INCOMING` - หนังสือรับจากภายนอก
  3. `OUTGOING` - หนังสือส่งภายนอก
  4. `COMMAND` - คำสั่งคณะ
  5. `ANNOUNCEMENT` - ประกาศคณะ
- กำหนดระดับชั้นความเร็ว:
  - `NORMAL` (ปกติ)
  - `URGENT` (ด่วน)
  - `VERY_URGENT` (ด่วนมาก)
  - `IMMEDIATE` (ด่วนที่สุด)
- กำหนดระดับชั้นความลับ:
  - `NORMAL` (ปกติ)
  - `CONFIDENTIAL` (ลับ)
  - `SECRET` (ลับมาก)
- แนบไฟล์เอกสารหลัก (PDF) และเอกสารประกอบเพิ่มเติม (Supporting Documents)
- บันทึกเป็นร่าง (Draft) เพื่อแก้ไขต่อ หรือยื่นเสนอเรื่องเข้าสู่เวิร์กโฟลว์ทันที (Submit)

### FR2: ระบบออกเลขทะเบียนสารบรรณอัตโนมัติ (Document Auto-Numbering)
- ออกเลขทะเบียนตามรูปแบบมาตรฐานงานสารบรรณ เช่น:
  - บันทึกข้อความ: `อว 0604.01/ว [ลำดับ]/[ปี พ.ศ.]`
  - หนังสือรับเข้า: `รับที่ [ลำดับ]/[ปี พ.ศ.]`
  - หนังสือส่งออก: `อว 0604.01/[ลำดับ]`
  - คำสั่งคณะ: `คำสั่งที่ [ลำดับ]/[ปี พ.ศ.]`
- รันเลขลำดับอัตโนมัติแบบ Atomic Lock ป้องกันเลขซ้ำแม้มีการกดบันทึกพร้อมกัน และรีเซ็ตลำดับใหม่เมื่อขึ้นปี พ.ศ. ใหม่

### FR3: เวิร์กโฟลว์การเกษียนหนังสือและส่งต่อเรื่อง (Routing & Endorsements)
- การแทงเรื่อง/เกษียนความเห็น (Endorsement Note):
  - พิมพ์ข้อความบันทึกความเห็น (e.g. "เห็นควรอนุมัติ", "มอบหัวหน้างานการเงินดำเนินการ")
  - เลือกผู้รับเรื่องในขั้นตอนถัดไป (Next Assignee)
  - เลือกการดำเนินการ:
    - **เกษียนและส่งต่อ (Forward / Endorse)**
    - **ส่งกลับแก้ไข (Return for Revision)** พร้อมระบุข้อความแก้ไข
    - **อนุมัติ / ลงนาม (Approve)**
    - **ไม่อนุมัติ (Reject)** พร้อมระบุเหตุผล

### FR4: ไทม์ไลน์และประวัติการเดินทางของเอกสาร (Audit Trail & Timeline)
- แสดงประวัติการดำเนินการแบบ Visual Step Timeline:
  - ใครเป็นผู้สร้างเรื่อง วันที่และเวลา
  - บันทึกความเห็นของแต่ละลำดับชั้น พร้อมชื่อ-ตำแหน่ง และวันเวลาที่เกษียนเรื่อง
  - สถานะปัจจุบันตกอยู่ที่โต๊ะทำงานของใคร

### FR5: แดชบอร์ดกล่องเอกสาร (Inbox & Filing Console)
- แบ่งแท็บการจัดการชัดเจน:
  1. **กล่องเรื่องรอลงนาม / ดำเนินการ (Inbox / Action Required)**: แสดงเอกสารที่ถูกแทงเรื่องมาถึงตนเอง
  2. **เรื่องที่ฉันเสนอ (My Submissions)**: ติดตามสถานะเอกสารที่ตนเองเป็นผู้ยื่น
  3. **ทะเบียนสารบรรณกลาง (Central Registry)**: สำหรับเจ้าหน้าที่สารบรรณ ค้นหา เรียกดูเอกสารทั้งหมดตามประเภทและปี
  4. **เอกสารเสร็จสิ้นแล้ว (Archive / Completed)**: เอกสารที่ลงนามอนุมัติสมบูรณ์แล้ว

## 4. ข้อกำหนดด้านความปลอดภัยและสถาปัตยกรรม (Non-Functional Requirements)

1. **Multi-Tenancy Isolation**: เอกสารทุกฉบับต้องมี `tenant_id` และถูกกรองด้วย Tenant ID ของผู้ใช้ที่ล็อกอินเสมอ
2. **Data Integrity & Concurrency**: การออกเลขสารบรรณต้องรันใน DB Transaction พร้อม optimistic/pessimistic locking เพื่อป้องกัน duplicate sequence numbers
3. **Audit Logging**: ทุกการเปลี่ยนสถานะเอกสาร (`SUBMITTED` → `IN_REVIEW` → `APPROVED` / `REJECTED`) ต้องบันทึกลงตาราง `audit_logs`
4. **Access Control**: เอกสารที่มีชั้นความลับ `CONFIDENTIAL` หรือ `SECRET` ผู้มีสิทธิ์เปิดอ่านต้องเป็นผู้สร้าง ผู้เกี่ยวข้องในสายเกษียน หรือผู้มีสิทธิ์ `document:manage` เท่านั้น

## 5. เกณฑ์การตรวจรับงาน (Acceptance Criteria)

- [ ] **AC-1**: ผู้ใช้งานสามารถสร้างบันทึกข้อความ แนบไฟล์ PDF และส่งเรื่องเข้าสู่ระบบได้สำเร็จ
- [ ] **AC-2**: ระบบสามารถออกเลขทะเบียนสารบรรณอัตโนมัติถูกต้องตามประเภทและปี พ.ศ. โดยไม่มีเลขข้ามหรือเลขซ้ำ
- [ ] **AC-3**: ผู้รับเรื่องสามารถเขียนข้อความเกษียนหนังสือและส่งต่อเรื่องไปยังผู้บริหารลำดับถัดไปได้
- [ ] **AC-4**: ผู้บริหารสามารถลงนามอนุมัติ (Approve) หรือส่งกลับแก้ไข (Return) ได้ พร้อมเปลี่ยนสถานะเอกสารแบบ Real-time
- [ ] **AC-5**: แสดง Visual Timeline ประวัติการเกษียนหนังสืออย่างถูกต้อง ครบถ้วนทั้งชื่อ วันเวลา และความเห็น
- [ ] **AC-6**: ผ่านการตรวจสอบ Quality Gates ทั้งหมด: `type-check`, `lint`, `deps:check`, และ `test` 100%
